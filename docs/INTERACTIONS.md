参考用户给出的六种交互描述实现；视频链接在本次工具环境中无法直接播放，因此没有逐帧复刻。

| 灵感 | 本次处理 |
| --- | --- |
| 完成反馈按钮 | 主列表和悬浮预览共用完成按钮。按压轻微缩小；保存确认后用 120 毫秒描绘对勾，文字变为完成态；需要离开列表的行用约 240 毫秒完成反馈与折叠退场。 |
| 勾选联动 | 清单总数、分组数、侧栏智能清单/分类数、悬浮球角标和预览数量立即读取真实数据，并用 140 毫秒的小幅数字位移反馈。没有新增进度环或仪表盘。 |

| 圆形扩散转场 | 当前窗口与筛选直接切换更适合连续处理待办，没有增加扩散动画。 |

## 更新与保存

TaskStore → IPC 广播 → 主窗口与悬浮窗口的更新路径保持不变。任务筛选和保存数据格式也未改变。动画层只保留短暂的显示行，所有行显示的完成状态和所有数量始终来自已经确认的数据；不会为动画延迟保存。

同一项在请求尚未返回或反馈期间不重复提交，其他项可以连续完成。分类内从待办组移到已完成组时，同一 ID 只渲染一份，不会同时出现在两个分组。重复数据快照不重新计时，切换筛选会清理旧的退出行。隐藏窗口不积压退出动画，重新显示时读取当前状态。

保存失败时保持原状态并显示错误，输入或任务不会因假成功消失。动画状态不会写进任务文件。系统减少动态效果开启时，取消对勾描绘、数字滚动和行保留，直接显示最终状态。

## 可访问性

完成按钮仍能使用 Enter / Space，保留焦点样式与 `aria-pressed`。退出行不再接受重复操作；若键盘焦点在即将移除的行中，会转到下一项，没有下一项时转到添加入口或列表标题。不会抢走已转移到其他控件的焦点。主界面和预览均有可被辅助技术读取的完成反馈，状态并不只由颜色或动画表达。

- `tests/desktop/completion.spec.js`：动画未结束时已落盘、同帧重复点击、多项连续完成、焦点接续、分类移动、恢复、减少动态、失败反馈、跨窗口数字同步及重启状态保留。
